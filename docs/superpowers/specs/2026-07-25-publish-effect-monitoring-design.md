# 发布效果监测 3.5 设计

## 目标

为已发布的小红书或 RedNote 笔记建立本地效果监测任务，连续 30 天保存点赞、收藏和评论的公开互动快照，并在高交互 Web 仪表盘中展示趋势。

## 已确认范围

- 3.5 是独立的“发布效果监测”入口，默认展示任务列表。
- 一个任务只监测一篇笔记。创建时粘贴小红书或 RedNote HTTPS 链接；以读取到的笔记 ID 去重，重复链接打开既有任务。
- 创建后立即采集一次；按 Asia/Shanghai 每天 10:00 采集一次，持续 30 天。应用启动时补采当天缺失的有效任务。
- 仅统计点赞、收藏、评论的累计值和相较上个快照的增量。
- 不包含竞品平均表现、转发数、AI 效果分析、优化建议或一键优化。
- 任务和全部快照写入单一 `data/monitoring.json`；写入使用临时文件后替换，避免半写入文件。
- 任务可删除，需二次确认；删除后不保留回收站。
- 采集失败时不写快照、不删除历史，展示失败原因；后续每日调度仍重试，并支持立即重试。

## 方案选择

### 方案 A：本地 JSON + 应用内调度器（采用）

新增小型文件存储服务与监测服务。FastAPI 生命周期启动调度循环，调用既有 `RedbookCLI.read_note` 和 `normalize_detail` 获取互动数据。浏览器继续使用原生 JavaScript，通过 ECharts 绘制图表。

优点是没有新的服务、数据库或前端框架，复用现有本地运行模型。缺点是应用不运行时不会采集；重新启动时只能补采当天当前值，不能还原离线期间的每日值。

### 方案 B：SQLite + 独立后台进程

可靠性和查询能力更强，但与已确认的 JSON 存储要求冲突，也引入额外运行方式，超出首版。

### 方案 C：迁移到 Vue/Spring 后再开发

可获得完整前端工程化能力，但没有业务必要，成本远大于图表和任务管理需求，不采用。

## 架构

```text
浏览器
  ├─ 任务列表 / 新建任务 / 删除任务
  └─ 任务仪表盘（ECharts）
          │ HTTP
FastAPI 路由
  ├─ MonitoringService：创建、读取、重试、删除、调度
  ├─ MonitoringStore：JSON 读写、原子替换
  └─ RedbookCLI + normalizer：复用笔记详情抓取
          │
data/monitoring.json
```

## 数据模型

`MonitoringTask` 保存 `task_id`、`note_id`、原始 `web_url`、笔记标题和封面、创建时间、监测开始和结束时间、最后成功采集时间、当前状态以及最后错误。

`InteractionSnapshot` 保存采集时间、点赞数、收藏数和评论数。一个任务在同一北京时间自然日最多有一个成功快照；重试只会替换或跳过当天记录，不会制造重复点。

顶层 JSON 带 `version: 1` 和 `tasks` 数组。档案不存在时视为空档案；无效 JSON 返回可理解的本地档案错误，不覆盖原文件。

## API

- `GET /api/monitoring/tasks`：按创建时间倒序返回任务摘要。
- `POST /api/monitoring/tasks`：接收 `web_url`，读取笔记、按笔记 ID 去重、保存任务并尝试首次采集。首次采集失败仍返回任务及错误状态。
- `GET /api/monitoring/tasks/{task_id}`：返回任务详情和快照序列。
- `POST /api/monitoring/tasks/{task_id}/refresh`：立即重试采集，成功时写入当天快照。
- `DELETE /api/monitoring/tasks/{task_id}`：永久删除任务与快照。

错误响应沿用现有 `ApiErrorBody`。链接校验沿用现有小红书/RedNote HTTPS 域名规则。

## 调度与失败语义

应用启动时执行补采：仅处理仍在 30 天监测期内、且当天没有成功快照的任务。之后调度器每天北京时间 10:00 处理相同集合。调度周期不因单任务失败中断。

对 CAPTCHA、会话失效、网络超时、笔记不可见和解析失败，任务记录 `last_error` 与失败时间，但不追加零值快照。成功采集清除错误状态。任务到期后状态为已完成且不再调度。

## Web 体验

任务列表显示进行中和已完成状态、封面、标题、创建日期、最近更新时间与失败提示。新建任务以链接输入框发起；重复链接进入原任务；删除前使用原生确认对话框。

详情页顶部是三张指标卡，展示当前累计值和相对上一快照的增量。图表使用 ECharts 单指标平滑面积折线图：点赞、收藏、评论切换；近 7 天、近 30 天、全部监测期切换；拖拽缩放、悬停 Tooltip 与日期/累计/增量明细。首次快照和空数据提供说明状态。动画限定于指标切换和首次绘制，并遵守 `prefers-reduced-motion`。

现有浅色紫蓝视觉系统、侧边栏和原生 JavaScript 组件继续使用。ECharts 以本地前端资源提供，不依赖 CDN。

## 测试

- 单元测试 JSON 档案：初始化、读取、原子写入、任务去重、删除、同日快照去重、坏文件错误。
- 单元测试监测服务：首次采集成功/失败、立即重试、到期不采集、启动补采。
- API 测试：任务 CRUD、链接校验、重复笔记、失败保留任务。
- 前端以静态检查和浏览器手工验证覆盖任务列表、空态、失败态、图表切换、时间范围、缩放和窄屏布局。

## 非目标

- 竞品基线或竞品表现对比。
- 阅读量、互动率、转化率、分享数。
- AI 分析或内容重新生成。
- 服务离线期间的逐日历史数据回填。
- 多用户、云端同步或公开部署。
